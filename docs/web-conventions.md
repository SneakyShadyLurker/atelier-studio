# Web UI conventions

Conventions and the breakpoint contract for the React web app. The locked UI source is [`docs/handoff/`](./handoff/README.md).

- **`shared/src/index.ts` is the public wire barrel**. Batch, tile, story and prompt-library response types derive from shared `zod/mini` schemas in `shared/src/wireSchemas.ts` (the explicit `@atelier/shared/wire-schemas` subpath). Every public type joins the `_NoUserId*` trap battery. Client-only state (`AppView`, hook return shapes, URL state) stays web-local.
- **Active work refreshes independently of history pagination.** `useHistoryRefresh` owns the adaptive 3–30s poll through `POST /history/refresh`; `historyOpts` keeps ordinary focus/invalidation refetches and cursor paging. Polling failures use the existing history error/Retry interface; manual Retry retains the authoritative history refetch and recovers the refresh query. When no work remains, reset obsolete polling errors. History-changing mutations use `HISTORY_WRITE_MUTATION_KEY`, including custom hooks built on `useToastMutation`; streaming generation stays outside that fence. A delayed refresh applies only to batches unchanged since request start and cannot restore removed tiles or overwrite optimistic collection/pin state. Older story discoveries outside an unfinished cursor window wait for normal pagination.
- **Navigation has one owner.** Zustand and the URL hold the requested view; `useDeferredValue` supplies the render snapshot. Keep view-dependent queries aligned with that snapshot and the stale view inert. Sidebar history actions become read-only while navigation and the composer stay usable, preserving keyboard focus. Wrapping a Zustand write in `startTransition` does not defer it. Heavy destinations retain their existing lazy boundaries; draft dialogs and the picker stay bundled to avoid chunk failures during editing.
- **Reuse native input contracts.** Prompt-library name inputs use `PROMPT_LIBRARY_NAME_MAX_CHARS`, and save guards also reject restored over-length values. A blank dimension name means no rename; tag and description edits retain the saved name. Enter/Escape handlers must respect `isImeComposing` before committing or dismissing input.
- **`modelById` (`Map<string, Model>`, built in `App.tsx`) is a required prop** on Batch/Canvas/Lightbox. no `.find` fallback; if it's missing the caller is buggy. De-registered models still resolve via the `batch.modelLabel` snapshot inside Batch.
- **Use design tokens, not literal rgba**. `--scrim*` (ink tint `rgba(27,29,32,x)`), `--glass-on-dark-*`, `--shadow-photo`, `--plate-mark` (the debossed plate frame) and `--etch-ink` (the art-mask tint) in `tokens.css`. **Radius by role**: `--radius-control` (buttons, chips, kbd, inputs, menu rows, wells), `--radius-tile` (tiles, thumbnails, plates), `--radius-panel` (popovers, dialog cards, toasts, composer, content panels), `--radius-sheet` (phone sheet top corners); the old `--radius-3/4/7/lg/14` and bare `--radius` are gone (`designSystemDrift.test.ts`). **Motion reads tokens**: `--dur-*`, `--ease-*`, the amplitudes `--m-shift`, `--m-scale`, `--m-blur`, `--m-press*`, and the loop cadences `--cadence-loop` / `--cadence-loop-fast` (every `infinite` animation reads one; reduced motion leaves them alone and the owner stops or swaps the loop); keyframes and `animation`/`transition` declarations never hard-code a scale or blur (derive from `--m-*`; the LoadingTile preview ladder is the deliberate exception). The reduced-motion rule set in `styles/motion.css` also sets `::view-transition-group(*) { animation: none; }`, because React does not honour reduced motion. The **handoff prototype lives in two files**: `docs/handoff/design/index.html` (`:root` block only) + the CSS template-literal inside `app.js`; a prototype change touches both, and `tokens.css` must mirror the `:root` block verbatim (`web/test/tokens.test.ts` enforces byte parity). **Borders split by role**: `--line`/`--line-2` are decorative dividers; an interactive control's own boundary uses `--line-control`, which clears the WCAG 1.4.11 3:1 minimum against `--bg`, `--bg-elev` and `--bg-sunk`. don't reach for a divider token on a button.
- **Mobile breakpoint: phone = `(width < 768px)`, desktop = `(width >= 768px)`, hardcoded across four update categories**. change all together: `tokens.css --bp-phone` (doc-only, `767px` = widest integer phone width, mirrored from the locked handoff), `useIsPhone.ts`, `web/src/styles/buttons.module.css` + `dialog` style modules, and every component CSS module's `@media (width < 768px)` / `(width >= 768px)`. Use Media Queries Level 4 range syntax, never a `max-width: 767px` / `min-width: 768px` pair: a fractional viewport width between the two matches neither (`web/src/breakpoint-invariant.test.ts` enforces it). **Width is not the only axis**: touch is gated on capability through one media query, `@media (hover: none), (any-pointer: coarse)` (the touch gate). Every 44px touch floor and every resting-visible hover affordance lives under it, after the base rule it raises: `(hover: none)` catches phones and iPad, `(any-pointer: coarse)` catches iPad with a keyboard (which reports `hover: hover`) and touch laptops. A `(width < 768px)` block carries phone geometry only (layout, 16px input fonts, padding); the drawer's close button and the managed header's arrow-only phone Back are the 44px rules allowlisted there. `web/src/breakpoint-invariant.test.ts` requires every hover/pointer query to be the gate (hover-capable `(hover: hover)` affordances and the Composer's no-keyboard shortcut hint are the named exceptions) and every 44px rule inside a media query to sit under it. `isTouchViewport` (`(hover: none)`) still answers "is there a soft keyboard" for auto-focus. A short desktop window matches the phone *geometry* and has neither.
- **Type: no `text-transform: uppercase`, no middle-dot joins, mono only for kbd, template tokens and the resolved prompt.** Labels are sentence-case source text in real small caps; meta is a list; readouts (seed, counts, timers) are sans tabular numerals; buttons say the verb, no arrow glyph. No subtitles: a heading stands alone; counts and identifiers move into body, fields or Meta lists, or are dropped; field labels, body paragraphs and one-sentence notes are not subtitles.
- **Limited-height image Composer**: only `(width >= 768px) and (height <= 620px)` compacts the image body, sharing Attach and the prompt when there are no references and limiting the prompt to three lines plus padding. That no-reference textarea reserves the existing absolute Minimize hit region with `width: calc(100% - 28px - 16px)`, using `44px` instead of `28px` under the capability gate. Phone, inventory/error-only and video bodies retain their layouts; the textarea's 44px touch minimum stays under the capability gate. Soft informational toasts omit their glyph; success/default keeps the check and error keeps the alert, with existing lifecycle and motion unchanged.
- **Don't re-roll shared scaffolds.** Canonical owners:
  - Type primitives → `styles/type.module.css` (`.label` small caps, `.meta` list, `.numeral` tabular readout, `.kbd`), composed by modules. Meta strings → `components/Meta` (`<Meta items lead>`, drops empty items; on-dark hosts retint through `--meta-ink` / `--meta-ink-strong`).
  - Etched art → `components/Etching` (`<Etching id>`, `EtchingId`), the only owner of an artwork `mask` (WebP alpha masks in `assets/etch/`). Empty, error, crash and loading presentation → `components/StateView` (`art` puts the etching in the `.plate`; `restPlate` is the empty plate at rest for loading; `glyph` for icon-only fallbacks); `LoadingState` / `ErrorState` wrap it.
  - Reduced motion → the single rule set at the end of `styles/motion.css` (collapses every `--m-*`, `--dur-*` and `--ease-*`, and the `::view-transition-*` pseudos); sheet slides and looping loaders, which no token reaches, add an owner-local branch. View navigation → the keyed `<ViewTransition>` around the view stage in `App.tsx`, direction from `lib/viewNav.ts` `viewNavDirection`. Composer has a separate opacity-only enter/exit boundary for managed-view navigation; its `composer-frame` update class interpolates the frame's footprint when a part enters or leaves or the mode body (`composer-body`) swaps, and typing never animates it (the prompt is not in the Composer's parts snapshot). Both update classes are keyed to the `composer-parts` Transition type (`lib/composerMotion.ts`), which only the Composer's parts commit carries (a typed `startTransition`, because `useDeferredValue` cannot carry a type), so any other Transition leaves them unnamed: a captured element is not hit-testable until its animation ends, and a frame captured while a batch enters the feed would swallow Generate presses. Conditional parts (Composer banner, ref chips, queue chip and list, collapsed-bar badges, busy pill; Batch queue badge, pin and Play master; picker phase bodies and warnings; Lightbox reference strip and image error; Sidebar empty/error state via `StateView`; Diagnosis card; Settings panel states; Connection result and test report sections) → an unnamed `<ViewTransition default="none" enter="part-enter" exit="part-exit">` rendered from the surface's one deferred snapshot; urgent input (typing, focus, ticked boxes) never goes through it. A part inside a hidden surface (the collapsed Composer form, the closed queue) is kept out of the capture with `view-transition-name: none !important`, because a snapshot ignores its ancestors' opacity and clip. List reflow and removal → a `<ViewTransition>` per Canvas batch row (`Canvas`), per feed tile (`Batch`) and per Archive tile (`Archive`), classes `tile-move` (update), `tile-exit`, `tile-enter` in `motion.css`; each surface renders one `useDeferredValue` snapshot so the removal commits in a Transition, and the boundary sits above every DOM node it animates (React runs enter/exit only there). The deferred snapshot is for rendering only: every handler that mutates state, resolves an action or computes indexes or ids reads the live value (live props, or `useAtelierStore.getState()` at click time), and a control shown from a stale snapshot is inert or validated against the live value before it acts, because React holds a Transition's commit until a running view transition finishes (about `--dur-sheet`), not one frame. Where deleting a container would take the animated boundary with it, the container gets its own exit boundary: each Archive virtual row (`default="none" exit="tile-exit"`, so a removed row's sole tile still exits), and the Canvas feed column beside the empty state (the last batch's removal exits the column while `EmptyCanvas` enters with `part-enter`). Feed boundaries stay unnamed so a batch two scopes share never pairs across a view swap; Archive tiles are named `tile-<id>` with `share` so a tile that re-chunks into another virtual row moves as one group. The captures are exactly these: view stage, Composer frame and body, batch rows, the feed column and empty state, Archive rows, tiles, and the listed parts (guard in `designSystemDrift.test.ts`); React alone starts transitions and names boundaries. React waits for a running view transition and batches the Transitions committed meanwhile into the next one; a synchronous re-render while one prepares skips it, so the feed virtualizers run with `useFlushSync: false` (`lib/feedAnchor.ts`). Canvas rows sit in normal flow inside one window translated to the first rendered row (TanStack's dynamic-size layout), so a batch that shrinks or leaves moves the rows below in the same Transition commit and their boundaries animate it; per-row `translateY` would move them only after a later ResizeObserver measurement, outside the Transition. Placeholder data (`keepPreviousData` showing the previous scope or search) rides in the Canvas snapshot and keys the row list, so the commit that replaces it remounts the list instead of playing row exits and entrances; the view stage carries the swap. The sidebar, toasts and overlays stay outside every capture except their listed parts (the rail state, the Lightbox chrome, the picker phases, the report sections), which are captured only while they enter or leave.
  - Modal scaffold → `components/DialogShell/`. a real `<dialog>` opened with `showModal()`, so **Tab containment, background inerting, and top-layer stacking come from the platform** (`trapFocus`/`autoFocus` props are gone; `useFocusTrap` remains the tool for surfaces the top layer does NOT cover. Sidebar drawer, popovers, the Lightbox's inner chrome). Three things stay ours by design: (1) **Escape**. the native `cancel` event is `preventDefault`ed so the three-mechanism nesting discipline below stays authoritative; (2) **exit choreography** (`useExitTransition`). the `overlay` transition property is Chromium-only; (3) **focus restore**. DialogShell captures the opener in its LAYOUT effect immediately before `showModal()` (a passive effect runs after the dialog already holds focus and would capture a control inside it), and the platform's own restore doesn't survive React removing the node in the same commit. `useModalChrome({ nativeModal: true })` therefore skips both its inert sweep and its focus save/restore; popovers/drawers leave it off and still need both. Any CSS class used as a DialogShell backdrop must carry the UA `<dialog>` resets (`styles/dialog.module.css`). DialogShell is not for popovers. A dialog's row of rectangular choices (a label around a visually hidden radio, or an `aria-pressed` toggle button) composes `dialog.module.css .choiceChip`.
  - Inline create/rename → `hooks/useInlineEdit.ts` (`commitOnBlur` is the divergence prop). Vertical drag-reorder → `hooks/useVerticalDragReorder.ts` (PromptManager's `useRowReorder.ts` is the index-callback adapter).
  - Focus-deferral → `lib/focus.ts` `runWhenReachable` (never `setTimeout(focus, 0)`). Ref-image attach → `hooks/useAttachRefImages.ts`. Tile-blob fetch → `api/images.ts` `fetchImageBlob`. Global keyboard → `hooks/useKeyboard.ts` (extend, don't fork). Image zoom/pan gestures → `hooks/useImageZoom.ts` over pure math in `lib/imageZoom.ts` (no zoom/pan library. see the Lightbox zoom section in `docs/handoff/README.md`). Toasts → `store/atelier.ts addToast`; the "Archived" toast with Undo → `hooks/useArchiveUndoToast.ts`. Tooltips → `data-tip` + `data-tip-place` (placements locked in `lib/tooltip.ts`; the label is a sentence-case sans label on `--ink`, no mono).
  - Action overflow menu → `components/OverflowMenu/` (`role=menu` popover/sheet, grouped rows, roving Arrow/Home/End); owners such as `BatchOverflowMenu` and the text-model rows pass only their items. Native anchor relationships and popover lifecycle → `hooks/useNativeAnchor.ts`; placement, edge alternatives, trigger width and height budgets → `styles/anchors.module.css`. ChipSelect stays in the page layer beneath Undo with a declarative instance name. See [Native anchors](./native-anchors.md) for the complete surface inventory and browser boundary.
  - Long-text prose reveal → `components/Batch/BatchPrompt.tsx` (cursor-tracking `role=tooltip` card; the `data-tip` primitive is for short labels, wraps at viewport edges and must NEVER carry prompt-length text).
  - Overlay Escape routing: top-level overlay → `useModalChrome` (also inerts the background); overlay nested inside a `useModalChrome` overlay → `useNestedDialogEscape`; overlay nested under the keyboard registry → `useKeyboardScoped('<scope>', 'Escape', …)`. Three mechanisms by design. pick by nesting context, don't fork a fourth.
  - **A sheet that renders a backdrop MUST disable `useOutsidePointer` in that mode** (`enabled: open && !isPhone` / `&& !isSheet`) and dismiss from the backdrop's CLICK. `useOutsidePointer` fires on `pointerdown`, which precedes a tap's click: dismissing there unmounts the backdrop mid-tap and WebKit dispatches the click on whatever is now under the finger, bleeding the tap into the layer below. Sheets also pad their bottom with `env(safe-area-inset-bottom)`. `viewport-fit=cover` otherwise runs the last action row under the home indicator. Both rules are in the `useOutsidePointer` doc block and `docs/handoff/README.md`.
  - **No `scroll-snap` on the batch feeds.** The canvas is virtualized with async row measurement and reserves a composer-sized bottom padding; snap points re-target every programmatic and user scroll to a batch's top, which parks the newest tile's actions behind the composer and re-snaps on each re-measure. Locked by `web/e2e/phone-feed.spec.ts`.
- **Action surfaces are always-reachable inline icon buttons** (`buttons.module.css .iconAction`/`.tileAction`, each with `data-tip` + `aria-label`). no hover-ONLY affordances, no context menu. "Reachable" means every input modality has a path: tile actions may rest hidden on pointer devices but MUST reveal on `:hover` AND `:focus-within`, and rest visible under the touch gate `@media (hover: none), (any-pointer: coarse)` (iPad has no hover). Header-level actions stay literally always visible. Keep one or two high-frequency actions out front (e.g. the batch header shows Archive + a pin badge only when pinned) and collapse the rest behind a single **More (⋯)** button opening an anchored popover/sheet (`OverflowMenu` for multi-action clusters; `MovePopover` for a single-purpose picker). AI actions (`btn.ai`) stay enabled without a text model: `hooks/useTextModelGate.ts` reports `availability` ('none' only when `/text-models` lists zero models) and `admin`, and on 'none' the trigger opens `components/TextModelNote` anchored to the pressed button (phone: a sheet; after a phone More menu, its More button). Admins get "Set up text models" (`lib/textModelsNav.ts goToTextModels`, after the host's own overlay exits); everyone else, and an unsettled admin probe, reads "Ask your admin to connect a text model." Any other routing outcome stays with the server's 409 toast. The host passes `escape` by its nesting (Escape routing below).
- **Three planes, four overlay types.** Planes: Library = `Sidebar`; Canvas = `Canvas`/`Archive`/`PromptManager`/`Lightbox`; Composer = `Composer`/`PromptPicker`/`RefImageRow`/`EnhanceControl`. Composer state lives in the existing `ComposerDraft` slice. add fields, never fork. Overlays: popover / sheet (mobile popover) / dialog (`DialogShell`) / viewer (Lightbox). No fifth overlay grammar or new plane without a design pass.
- **Prompt Library scroll-surface contract**. fixed `data-zone="head|entry|body|foot"` zones, single scrolling body, 14px mask fade (`--scroll-fade-mask`; the batch feeds declare the gradient on the scroller with the registered `--scroll-fade-top` stop, which a scroll-driven `atelier-scroll-edge` animation behind `@supports (animation-timeline: scroll())` opens to 0 at rest), fixed-height controls, drag-reorder via local drafts (never server mutations). Used by the three PromptManager editors, PromptPicker, and the Sidebar rail. Limited-height exceptions keep content reachable: the Library rail body below its fixed sidebar header scrolls only when needed, including navigation and footer, while history retains its own scroller and one-row content minimum (`--rail-history-min-h: 73px`) plus unchanged host bottom padding (18px in production, 80px in the prototype); at widths of 768px and above, the Template Editor panel scrolls only when exhausted, with contained overscroll and a six-line textarea minimum plus padding and border (`--template-body-min-h`), allowing its header and Save to scroll away. At the same widths, the Variable List and Dimension panels contain overscroll and scroll only when their fixed chrome plus the usable body minimum cannot fit: `--list-dimension-body-min-h: 72px` reserves a 44px row plus 14px padding at both edges, with matching body scroll padding for native reveals through the retained mask. Their header and toolbar stay in normal flow; the flex-shrinking list body keeps ordinary long-list scrolling, preserving header and toolbar positions in normal-height layouts. Phone editor scrolling, touch targets, keyboard behavior and motion remain unchanged. Extend it for new Prompt Library UI; assert layout via `[data-zone]` containment (happy-dom can't verify scroll/flex). An empty resource tab renders its `StateView` alone across both columns, its create action the only one: the list pane (and its New button) stays out until a row exists or the inline name field opens; the Dimensions tab keeps Propose Dimensions in its header row meanwhile.
- **Archive reuses the Library rail chrome byte-identically but context-gates rows** via the pure `buildLibraryRows(collections, summary, isArchive)` (`Sidebar/rows.ts`, single source of truth). In Archive: Unsorted always renders; Pinned gates on `archivedPinnedCount > 0`; a collection renders only if `archivedCount > 0`; no New collection row. Counts use `archived*Count`; Pinned uses the scope-correct count, never a cross-scope OR. Archive + Prompt Library hide the sidebar feed (`hideFeed`). URL grammar: `?view=archive[&archive=unsorted|pinned | &c=<id>]`. Don't reintroduce Main↔Archive row parity or a flat-archive lock, and don't restructure rail chrome between modes (it must not jump). Archiving a single tile or a batch shows "Archived" with Undo (5s) when it archived tiles, which restores exactly the tile IDs that operation archived through the existing restore path, once; Archive all keeps a plain toast.
- **Every content column opens with `components/ManagedViewHeader`**: one visible serif `--text-xl` `<h2>` title that stands alone (no scope or count label beside it), an optional secondary back button, a right-action slot and one optional `titleAction` (the Prompt Library help button). On phones the action slot wraps to its own full-width row below the hamburger (taking back its clearance) while `titleAction` stays on the title row and the title wraps beside it. The image list (Canvas) titles itself with `scopeTitle(view, collections)` (`lib/viewChrome.ts`: Unsorted, Pinned or the bare collection name) on every form factor, so the title equals the active rail row; the Sidebar reads the same function, and "Feed" is not a UI word. `onBack` is optional; when given, `backLabel` is required and names where Back goes ("Back to <scope>"): Archive, Prompt Library and Text models go to Unsorted. Below 768px Back is the arrow alone in a 44px square, with the label as its `data-tip`, the label visually hidden but still its accessible name, so the title keeps one line. The header owns the collapsed-sidebar and phone hamburger clearance; hosts reserve no band of their own. Selected-state = 2px `--ink` bar; `--accent` is reserved for the AI button (`btn.ai`, `<Verb> <Noun>` naming; the sparkle is `<I.sparkle aria-hidden>` inside the button. never a literal `✦` in the label string, which screen readers would read out). The composer's Enhance button speaks the same vocabulary as a flat accent-ink segment (`EnhanceControl`). Extend `ManagedViewHeader`, don't hand-roll a per-view header.
- Managed views compose the header owner's shared `.inset` for their 36px desktop and 14px phone gutters. Overlay transitions compose `styles/surface.module.css`; preserve the exit hook and native popover/dialog lifecycle. Tune a surface only through `--surface-from`, `--surface-to` and `--surface-duration` on the element itself (the shared file keeps its defaults and its resting `opacity`/`transform` at zero specificity and the three non-inherited, because each composing module carries its own copy of it and a later copy must not reset an owner). User-action toast dismissals call the store's `dismissToast` (exit fade, one unmount, one `onDismiss`); `removeToast` is instant programmatic teardown. Composer uses intrinsic grid tracks with stable, inert hidden forms; media reveals wait for load/decode readiness. Height-auto reveals (Advanced, Referenced lists, option tags, Coverage and Diagnosis details, the Composer roll queue, the Add provider hints) go through `components/Disclosure` over `styles/disclosure.module.css`: a `0fr → 1fr` grid-track transition that stays mounted, inert and `aria-hidden` while closed, so it reverses mid-way; owners keep their toggle (`aria-expanded`, `aria-controls` → `id`) and move a parent's gap inside `contentClassName`. Never an instant `{open && …}` toggle or `interpolate-size` (Chromium only). Text that switches while its disclosure stays open (the Add provider URL hints) gets one disclosure per text, keyed by it: the old one closes while the next opens on the same track transition, so the height interpolates instead of snapping inside one open panel. Readouts and controls that appear after async data keep a reserved slot: the Lightbox size readout is a `min-width: 9ch` tabular slot (empty until decode, never "…") and its Zoom button is laid out for every image (`visibility: hidden`, `inert`, `aria-hidden` until zoom is worthwhile); the Lightbox reference strip and toolbar share one bottom column (`.dock`), so a wrapping toolbar pushes the strip up; the Composer's empty source slot and its thumb share one 64×64 footprint with the words in `.sourceMeta`; `InfiniteStatus` reserves its status line and the Retry row while more history can load (idle, loading, error), and its end state drops that reserve to just the hairline and label, because nothing can follow it; that footprint (`useStatusFootprint`) commits in the deferred render, with the rows of a parent that draws them from `useDeferredValue` (Canvas, Archive), while fetching reads the live flags; a re-test keeps the last connection result or model report in place, `aria-busy`, until the next one lands (`useHeldWhileRunning`).
- **Virtualization** (Canvas / Archive / PromptPicker template list / Sidebar feed, `@tanstack/react-virtual`). `getItemKey` off stable IDs (never index), with one exception: Archive grid rows are positional chunks of tiles, keyed by index so a removal re-chunks without deleting the row element (a deleted row would swallow the tile exit); tile identity lives in each tile's named `<ViewTransition>` (`share="tile-move"`); height reads `getTotalSize()` only when virtual items exist (`lib/virtualWindow.ts` owns that rule and the pre-measure fallback rows); Archive re-measures on `gridCols`. Off-screen nav routes through `virtualizer.scrollToIndex`, never `querySelector`. **The two batch feeds (Canvas + Sidebar rail) take their virtualizer anchoring from `lib/feedAnchor.ts`**. The feed is bottom-anchored: it reads oldest → newest, so new work is an append at the end, next to the composer, and an older page is a prepend. `anchorTo: 'end'` holds the reader's row still when older history loads above (the scroller runs `overflow-anchor: none`, the Canvas row window is absolutely positioned, and `overflow-anchor` isn't Baseline anyway). A Canvas width change (sidebar collapse, window resize) re-reads every rendered row's `offsetHeight` inside the synchronous scroller-rect callback (TanStack's `measureElement` without a ResizeObserver entry returns the cached size), so positions and the end anchor land before that frame paints, not one row-ResizeObserver commit later; `followOnAppend` sticks to the newest batch only when the reader was already within `FEED_SCROLL_END_THRESHOLD_PX` of the end, so a reader who scrolled up is never pulled down. Stable `getItemKey` is a hard requirement for it. `anchorTo` re-anchors only when the row set changes, using that render's `scrollMargin`, so a height change in the content above the list (the history status row reaching its end state) is held by `measureFeedScrollMargin`: both feeds key that measurement on `useStatusFootprint`, so it runs in the commit the row shrinks, and pay the change through the virtualizer's `scrollBy` (a raw `scrollTop` write is undone by its scroll reconcile), held on touch devices until `isScrolling` clears, since a scroll write cancels iOS momentum. Unmeasured rows enter at `estimateSize`, and a prepended row that renders inside the viewport pushes the reader by its estimate error, so keep the Sidebar's `SIDEBAR_ROW_HEIGHT` equal to a two-line row (`e2e/ui-polish.spec.ts` samples both feeds per frame while the last page lands). Entrance animations must NOT replay on view-swap or virtual remount. `lib/seenBatches.ts` is one module store (`useSeenBatches`, sessionStorage, FIFO-capped 500) shared by Canvas and the Sidebar rail: each feed marks the batch ids it renders from a `useEffect`, never during render (StrictMode), and each row captures its `seen` flag once at mount (`useState(seen)`) so a later mark never cuts a playing entrance short; a seen row carries `data-seen="true"`, which stops its entrance (Archive frames always carry it).
- **`content-visibility: auto` is NOT pixel-faithful here**. it replays one-shot entrance animations on scroll-into-view. Tried and reverted; `seenBatches` is the replacement. Native top-layer tooltip labels now escape ancestor clipping; the animation constraint remains.
