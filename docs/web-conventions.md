# Web UI conventions

Conventions and the breakpoint contract for the React web app. The locked UI source is [`docs/handoff/`](./handoff/README.md).

- **`shared/src/index.ts` is the public wire barrel**. Batch, tile, story and prompt-library response types derive from shared `zod/mini` schemas in `shared/src/wireSchemas.ts` (the explicit `@atelier/shared/wire-schemas` subpath). Every public type joins the `_NoUserId*` trap battery. Client-only state (`AppView`, hook return shapes, URL state) stays web-local.
- **Active work refreshes independently of history pagination.** `useHistoryRefresh` owns the adaptive 3–30s poll through `POST /history/refresh`; `historyOpts` keeps ordinary focus/invalidation refetches and cursor paging. Polling failures use the existing history error/Retry interface; manual Retry retains the authoritative history refetch and recovers the refresh query. When no work remains, reset obsolete polling errors. History-changing mutations use `HISTORY_WRITE_MUTATION_KEY`, including custom hooks built on `useToastMutation`; streaming generation stays outside that fence. A delayed refresh applies only to batches unchanged since request start and cannot restore removed tiles or overwrite optimistic collection/pin state. Older story discoveries outside an unfinished cursor window wait for normal pagination.
- **Navigation has one owner.** Zustand and the URL hold the requested view; `useDeferredValue` supplies the render snapshot. Keep view-dependent queries aligned with that snapshot and the stale view inert. Sidebar history actions become read-only while navigation and the composer stay usable, preserving keyboard focus. Wrapping a Zustand write in `startTransition` does not defer it. Heavy destinations retain their existing lazy boundaries; draft dialogs and the picker stay bundled to avoid chunk failures during editing.
- **Reuse native input contracts.** Prompt-library name inputs use `PROMPT_LIBRARY_NAME_MAX_CHARS`, and save guards also reject restored over-length values. A blank dimension name means no rename; tag and description edits retain the saved name. Enter/Escape handlers must respect `isImeComposing` before committing or dismissing input.
- **`modelById` (`Map<string, Model>`, built in `App.tsx`) is a required prop** on Batch/Canvas/Lightbox. no `.find` fallback; if it's missing the caller is buggy. De-registered models still resolve via the `batch.modelLabel` snapshot inside Batch.
- **Use design tokens, not literal rgba**. `--scrim*`, `--glass-on-dark-*`, `--shadow-photo` in `tokens.css`. The **handoff prototype lives in two files**: `docs/handoff/design/index.html` (`:root` block only) + the CSS template-literal inside `app.js`; a prototype change touches both, and `tokens.css` must mirror the `:root` block verbatim (`web/test/tokens.test.ts` enforces byte parity). **Borders split by role**: `--line`/`--line-2` are decorative dividers; an interactive control's own boundary uses `--line-control`, which clears the WCAG 1.4.11 3:1 minimum against `--bg`, `--bg-elev` and `--bg-sunk`. don't reach for a divider token on a button.
- **Mobile breakpoint: phone = `(width < 768px)`, desktop = `(width >= 768px)`, hardcoded across four update categories**. change all together: `tokens.css --bp-phone` (doc-only, `767px` = widest integer phone width, mirrored from the locked handoff), `useIsPhone.ts`, `web/src/styles/buttons.module.css` + `dialog` style modules, and every component CSS module's `@media (width < 768px)` / `(width >= 768px)`. Use Media Queries Level 4 range syntax, never a `max-width: 767px` / `min-width: 768px` pair: a fractional viewport width between the two matches neither (`web/src/breakpoint-invariant.test.ts` enforces it). **Width is not the only axis**: `(hover: none)` (`isTouchViewport`, and the `@media` blocks that raise controls to the 44px touch floor) answers "does this device have a soft keyboard / no hover", which is the honest gate for auto-focusing a text field or resting an affordance on hover. A short desktop window matches the phone *geometry* and has neither.
- **Don't re-roll shared scaffolds.** Canonical owners:
  - Modal scaffold → `components/DialogShell/`. a real `<dialog>` opened with `showModal()`, so **Tab containment, background inerting, and top-layer stacking come from the platform** (`trapFocus`/`autoFocus` props are gone; `useFocusTrap` remains the tool for surfaces the top layer does NOT cover. Sidebar drawer, popovers, the Lightbox's inner chrome). Three things stay ours by design: (1) **Escape**. the native `cancel` event is `preventDefault`ed so the three-mechanism nesting discipline below stays authoritative; (2) **exit choreography** (`useExitTransition`). the `overlay` transition property is Chromium-only; (3) **focus restore**. DialogShell captures the opener in its LAYOUT effect immediately before `showModal()` (a passive effect runs after the dialog already holds focus and would capture a control inside it), and the platform's own restore doesn't survive React removing the node in the same commit. `useModalChrome({ nativeModal: true })` therefore skips both its inert sweep and its focus save/restore; popovers/drawers leave it off and still need both. Any CSS class used as a DialogShell backdrop must carry the UA `<dialog>` resets (`styles/dialog.module.css`). DialogShell is not for popovers.
  - Inline create/rename → `hooks/useInlineEdit.ts` (`commitOnBlur` is the divergence prop). Vertical drag-reorder → `hooks/useVerticalDragReorder.ts` (PromptManager's `useRowReorder.ts` is the index-callback adapter).
  - Focus-deferral → `lib/focus.ts` `runWhenReachable` (never `setTimeout(focus, 0)`). Ref-image attach → `hooks/useAttachRefImages.ts`. Tile-blob fetch → `api/images.ts` `fetchImageBlob`. Global keyboard → `hooks/useKeyboard.ts` (extend, don't fork). Image zoom/pan gestures → `hooks/useImageZoom.ts` over pure math in `lib/imageZoom.ts` (no zoom/pan library. see the Lightbox zoom section in `docs/handoff/README.md`). Toasts → `store/atelier.ts addToast`. Tooltips → `data-tip` + `data-tip-place` (placements locked in `lib/tooltip.ts`).
  - Action overflow menu → `components/OverflowMenu/` (`role=menu` popover/sheet, grouped rows, roving Arrow/Home/End); owners such as `BatchOverflowMenu` and the text-model rows pass only their items. Native anchor relationships and popover lifecycle → `hooks/useNativeAnchor.ts`; placement, edge alternatives, trigger width and height budgets → `styles/anchors.module.css`. ChipSelect stays in the page layer beneath Undo with a declarative instance name. See [Native anchors](./native-anchors.md) for the complete surface inventory and browser boundary.
  - Long-text prose reveal → `components/Batch/BatchPrompt.tsx` (cursor-tracking `role=tooltip` card; the `data-tip` primitive is for short labels, wraps at viewport edges and must NEVER carry prompt-length text).
  - Overlay Escape routing: top-level overlay → `useModalChrome` (also inerts the background); overlay nested inside a `useModalChrome` overlay → `useNestedDialogEscape`; overlay nested under the keyboard registry → `useKeyboardScoped('<scope>', 'Escape', …)`. Three mechanisms by design. pick by nesting context, don't fork a fourth.
  - **A sheet that renders a backdrop MUST disable `useOutsidePointer` in that mode** (`enabled: open && !isPhone` / `&& !isSheet`) and dismiss from the backdrop's CLICK. `useOutsidePointer` fires on `pointerdown`, which precedes a tap's click: dismissing there unmounts the backdrop mid-tap and WebKit dispatches the click on whatever is now under the finger, bleeding the tap into the layer below. Sheets also pad their bottom with `env(safe-area-inset-bottom)`. `viewport-fit=cover` otherwise runs the last action row under the home indicator. Both rules are in the `useOutsidePointer` doc block and `docs/handoff/README.md`.
  - **No `scroll-snap` on the batch feeds.** The canvas is virtualized with async row measurement and reserves a composer-sized bottom padding; snap points re-target every programmatic and user scroll to a batch's top, which parks the newest tile's actions behind the composer and re-snaps on each re-measure. Locked by `web/e2e/phone-feed.spec.ts`.
- **Action surfaces are always-reachable inline icon buttons** (`buttons.module.css .iconAction`/`.tileAction`, each with `data-tip` + `aria-label`). no hover-ONLY affordances, no context menu. "Reachable" means every input modality has a path: tile actions may rest hidden on pointer devices but MUST reveal on `:hover` AND `:focus-within`, and rest visible under `@media (hover: none)` (iPad has no hover). Header-level actions stay literally always visible. Keep one or two high-frequency actions out front (e.g. the batch header shows Archive + a pin badge only when pinned) and collapse the rest behind a single **More (⋯)** button opening an anchored popover/sheet (`OverflowMenu` for multi-action clusters; `MovePopover` for a single-purpose picker).
- **Three planes, four overlay types.** Planes: Library = `Sidebar`; Canvas = `Canvas`/`Archive`/`PromptManager`/`Lightbox`; Composer = `Composer`/`PromptPicker`/`RefImageRow`/`EnhanceControl`. Composer state lives in the existing `ComposerDraft` slice. add fields, never fork. Overlays: popover / sheet (mobile popover) / dialog (`DialogShell`) / viewer (Lightbox). No fifth overlay grammar or new plane without a design pass.
- **Prompt Library scroll-surface contract**. fixed `data-zone="head|entry|body|foot"` zones, single scrolling body, 14px mask fade, fixed-height controls, drag-reorder via local drafts (never server mutations). Used by the three PromptManager editors, PromptPicker, and the Sidebar rail. Extend it for new Prompt Library UI; assert layout via `[data-zone]` containment (happy-dom can't verify scroll/flex).
- **Archive reuses the Library rail chrome byte-identically but context-gates rows** via the pure `buildLibraryRows(collections, summary, isArchive)` (`Sidebar/rows.ts`, single source of truth). In Archive: Unsorted always renders; Pinned gates on `archivedPinnedCount > 0`; a collection renders only if `archivedCount > 0`; no "+ New collection". Counts use `archived*Count`; Pinned uses the scope-correct count, never a cross-scope OR. Archive + Prompt Library hide the sidebar feed (`hideFeed`). URL grammar: `?view=archive[&archive=unsorted|pinned | &c=<id>]`. Don't reintroduce Main↔Archive row parity or a flat-archive lock, and don't restructure rail chrome between modes (it must not jump).
- **Archive + Prompt Library share `components/ManagedViewHeader`** (back button + a11y heading + scope label + right-action slot); both `onBack` → Unsorted. Selected-state = 2px `--ink` bar; `--accent` is reserved for the AI button (`btn.ai`, `<Verb> <Noun>` naming; the sparkle is `<I.sparkle aria-hidden>` inside the button. never a literal `✦` in the label string, which screen readers would read out). The composer's Enhance button speaks the same vocabulary as a flat accent-ink segment (`EnhanceControl`). Extend `ManagedViewHeader`, don't hand-roll a per-view header.
- **Virtualization** (Canvas / Archive / PromptPicker template list / Sidebar feed, `@tanstack/react-virtual`). `getItemKey` off stable IDs (never index); height reads `getTotalSize()` only when virtual items exist (`lib/virtualWindow.ts` owns that rule and the pre-measure fallback rows); Archive re-measures on `gridCols`. Off-screen nav routes through `virtualizer.scrollToIndex`, never `querySelector`. **The two batch feeds (Canvas + Sidebar rail) take their virtualizer anchoring from `lib/feedAnchor.ts`**. The feed is bottom-anchored: it reads oldest → newest, so new work is an append at the end, next to the composer, and an older page is a prepend. `anchorTo: 'end'` holds the reader's row still when older history loads above (the scroller runs `overflow-anchor: none`, rows are absolutely positioned, and `overflow-anchor` isn't Baseline anyway); `followOnAppend` sticks to the newest batch only when the reader was already within `FEED_SCROLL_END_THRESHOLD_PX` of the end, so a reader who scrolled up is never pulled down. Stable `getItemKey` is a hard requirement for it. Entrance animations must NOT replay on view-swap. `lib/seenBatches.ts` (sessionStorage, FIFO-capped 500) is hydrated on mount and written from a `useEffect`, never during render (StrictMode).
- **`content-visibility: auto` is NOT pixel-faithful here**. it replays one-shot entrance animations on scroll-into-view. Tried and reverted; `seenBatches` is the replacement. Native top-layer tooltip labels now escape ancestor clipping; the animation constraint remains.
