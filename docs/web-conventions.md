# Web UI conventions

Conventions and the breakpoint contract for the React web app. The locked UI source is [`docs/handoff/`](./handoff/README.md).

- **`shared/src/index.ts` is the public wire barrel**. Batch, tile, story and prompt-library response types derive from shared `zod/mini` schemas in `shared/src/wireSchemas.ts` (the explicit `@atelier/shared/wire-schemas` subpath). Every public type joins the `_NoUserId*` trap battery. Client-only state (`AppView`, hook return shapes, URL state) stays web-local.
- **Active work refreshes independently of history pagination.** `useHistoryRefresh` owns the adaptive 3–30s poll through `POST /history/refresh`; `historyOpts` keeps ordinary focus/invalidation refetches and cursor paging. Polling failures use the existing history error/Retry interface; manual Retry retains the authoritative history refetch and recovers the refresh query. When no work remains, reset obsolete polling errors. History-changing mutations use `HISTORY_WRITE_MUTATION_KEY`, including custom hooks built on `useToastMutation`; streaming generation stays outside that fence. The app's `MutationCache` (`createHistoryBroadcastMutationCache` in `hooks/broadcastHistory.ts`) posts an invalidate on `BroadcastChannel('atelier-history')` whenever such a write settles, and an accepted generation posts one too, so sibling tabs re-read the library (`invalidateLibrary`: history, archive, collection counts) without waiting for focus. The message keeps a string `batchId` (older bundles drop one without it). The receiver (sibling invalidates and cancels alike) runs one re-read at a time, a burst joining it plus one trailing read, and defers while its own history write is in flight, settle re-read included, because an earlier read would land pre-commit state over the write's optimistic patch; a `MutationCache` subscription runs the deferred re-read when the last write ends, success or failure. Before streaming generation inserts its row it cancels the scope's in-flight history read, as the other writers do: a refetch or `fetchNextPage` (which appends to the pages it started from) read before the row existed would otherwise erase it; a cancelled refetch (a settle or sibling re-read, a focus refetch) is re-issued once the row exists, while a cancelled next-page load is left to the pagination sentinel. Stream writes go through `historyCache.ts` `setHistory`, which keeps the scope's last server-read clock and any pending invalidation (`setQueryData` alone would mark the scope fresh and swallow a settled write's invalidation for the whole burst) and creates a missing scope cache only for the insert. Tile and status events reach every cached history scope that holds the batch (Unsorted, Pinned, a collection it was moved into, a search), and a clean stream settles with one bounded `POST /history/refresh` for its batch written into every scope that shows it, never a refetch of every loaded page. Optimistic writes (archive, cancel, move, pin) also land in every cached scope holding the batch and roll each back on failure. A tile cancel leaves the batch stream open (the server cancels that one tile and the stream delivers its `canceled` terminal); only a batch cancel aborts it. Every history re-read waits behind a pending history write: a settled write's own re-read while another write is still pending, the stream's settle fallback and the read a batch insert re-issues for an interrupted or invalidated scope all go through `invalidateHistoryBehindWrites` (`hooks/invalidateLibrary.ts`), which only marks every history scope stale, and the `MutationCache` subscription reads once no history write is pending; the sibling receiver also waits while its tab is hidden. Tiles only move loading → terminal, so the history cache's structural-sharing reconcile never lets a stale read regress a finished tile. A delayed refresh applies only to batches unchanged since request start and cannot restore removed tiles; its merge takes collection and pin from the server row, because the write fence already discards any response that overlapped a local write, so a change made in another tab or on another device converges on the next poll. The poll excludes batches this tab streams, skips a merge while a list read is in flight, keeps polling through fetch errors (recovery after a restart) and drops to a two-minute reconcile once every running batch is past the 30-minute stuck cap. Older story discoveries outside an unfinished cursor window wait for normal pagination, also when every loaded row was removed. Every settle or recovery re-read of history goes through `reReadHistory` (or `invalidateLibrary` for a settling write): it reads now, or marks history stale and reads once after the last pending history write settles. A failed optimistic history write rolls back by inverse operation (`MirrorChange` in `hooks/scopedHistoryMutation.ts`), never by restoring a snapshot: it re-inserts only what it removed and restores a field only where the row still holds its own optimistic value, so a concurrent insert, removal or page load survives. A tile cancel the server confirmed (an SSE `canceled` event or a successful cancel DELETE) is tombstoned, so no older history read shows it again: a loading copy for 5 minutes, a finished copy for 1 minute (after that a finished copy is a real restore, from any tab); a failed cancel leaves no tombstone, and a restore forgets the tombstones of the tiles it hands back (a cancel that raced the tile's completion archives the finished tile). `reconcileHistoryPages` keeps every cached scope in `created_at DESC, id DESC` order across page boundaries, so test fixtures must build pages in that order (distinct `createdAt`, newest first) or the cache re-places their rows. `useHistoryHeadProbe` (mounted by the app shell in a null leaf) reads one row of the active unfiltered scope every 60 s while the feed is visible and idle, and merges a batch started on another device; it discards its response when a history write started or the scope's data generation (`dataUpdateCount`) changed while a request was in flight.
- **Navigation has one owner.** Zustand and the URL hold the requested view; `useDeferredValue` supplies the render snapshot. Keep view-dependent queries aligned with that snapshot and the stale view inert. Sidebar history actions become read-only while navigation and the composer stay usable, preserving keyboard focus. Wrapping a Zustand write in `startTransition` does not defer it. Heavy destinations retain their existing lazy boundaries; draft dialogs and the picker stay bundled to avoid chunk failures during editing.
- **Reuse native input contracts.** Prompt-library name inputs use `PROMPT_LIBRARY_NAME_MAX_CHARS`, and save guards also reject restored over-length values. A blank dimension name means no rename; tag and description edits retain the saved name. Enter/Escape handlers must respect `isImeComposing` before committing or dismissing input.
- **`modelById` (`Map<string, Model>`, built in `App.tsx`) is a required prop** on Batch/Canvas/Lightbox. no `.find` fallback; if it's missing the caller is buggy. De-registered models still resolve via the `batch.modelLabel` snapshot inside Batch.
- **Use design tokens, not literal rgba**. `--scrim*` (ink tint `rgba(27,29,32,x)`), `--glass-on-dark-*`, `--shadow-photo`, `--plate-mark` (the debossed plate frame) and `--etch-ink` (the art-mask tint) in `tokens.css`. **Radius by role**: `--radius-control` (buttons, chips, kbd, inputs, menu rows, wells), `--radius-tile` (tiles, thumbnails, plates), `--radius-panel` (popovers, dialog cards, toasts, composer, content panels), `--radius-sheet` (phone sheet top corners); the old `--radius-3/4/7/lg/14` and bare `--radius` are gone (`designSystemDrift.test.ts`). **Motion reads tokens**: `--dur-*`, `--ease-*`, the amplitudes `--m-shift`, `--m-scale`, `--m-blur`, `--m-press*`, the loop cadences `--cadence-loop` / `--cadence-loop-fast` (every `infinite` animation reads one; reduced motion leaves them alone and the owner stops or swaps the loop), the loop curve `--ease-loop` (a rhythmic sweep, never a directional `--ease-*`) and the hover-intent delay `--delay-hover-intent` (tooltips); keyframes and `animation`/`transition` declarations never hard-code a scale or blur (derive from `--m-*`; the LoadingTile preview ladder is the deliberate exception). The reduced-motion rule set in `styles/motion.css` also sets `::view-transition-group(*) { animation: none; }`, because React does not honour reduced motion. The **handoff prototype lives in two files**: `docs/handoff/design/index.html` (`:root` block only) + the CSS template-literal inside `app.js`; a prototype change touches both, and `tokens.css` must mirror the `:root` block verbatim (`web/test/tokens.test.ts` enforces byte parity). **Borders split by role**: `--line`/`--line-2` are decorative dividers; an interactive control's own boundary uses `--line-control`, which clears the WCAG 1.4.11 3:1 minimum against `--bg`, `--bg-elev` and `--bg-sunk`. don't reach for a divider token on a button.
- **Mobile breakpoint: phone = `(width < 768px)`, desktop = `(width >= 768px)`, hardcoded across four update categories**. change all together: `tokens.css --bp-phone` (doc-only, `767px` = widest integer phone width, mirrored from the locked handoff), `useIsPhone.ts`, `web/src/styles/buttons.module.css` + `dialog` style modules, and every component CSS module's `@media (width < 768px)` / `(width >= 768px)`. Use Media Queries Level 4 range syntax, never a `max-width: 767px` / `min-width: 768px` pair: a fractional viewport width between the two matches neither (`web/src/breakpoint-invariant.test.ts` enforces it). **Width is not the only axis**: touch is gated on capability through one media query, `@media (hover: none), (any-pointer: coarse)` (the touch gate). Every 44px touch floor and every resting-visible hover affordance lives under it, after the base rule it raises: `(hover: none)` catches phones and iPad, `(any-pointer: coarse)` catches iPad with a keyboard (which reports `hover: hover`) and touch laptops. A `(width < 768px)` block carries phone geometry only (layout, 16px input fonts, padding); the drawer's close button and the managed header's arrow-only phone Back are the 44px rules allowlisted there. `web/src/breakpoint-invariant.test.ts` requires every hover/pointer query to be the gate (hover-capable `(hover: hover)` affordances and the Composer and empty-Canvas no-keyboard hints are the named exceptions) and every 44px rule inside a media query to sit under it. **Every `:hover` rule sits under `@media (hover: hover)`**: WebKit keeps `:hover` on a tapped control until the next tap elsewhere, which read as a stuck state; `:active` (the press), `:focus-visible` and the disabled/busy looks stay unconditional, and hover rules skip `:disabled`, `[aria-disabled='true']` and `[aria-busy='true']`. A busy control is `aria-busy` + `aria-disabled` with a click guard, never `disabled`: a focused control that becomes disabled drops keyboard focus to `<body>`. `isTouchViewport` (`(hover: none)`) still answers "is there a soft keyboard" for auto-focus. A short desktop window matches the phone *geometry* and has neither.
- **Approved Move and copy exceptions**: Move create alone adds a visible ink-primary Move beside its flexible input (6px gap, 36px height, 44px input/button minimum under the touch gate). Enter and Move share the inline-edit commit and one synchronous create-and-move guard; pending retains the name, blocks editing and repeated submission, and failure allows deliberate retry with the actual error toast. Focus inside the row retains the draft, outside blur cancels without focus theft; rename, IME, Escape nesting, anchors and motion stay unchanged. Sidebar delete titles quote the literal collection name and wrap anywhere without a count; fallback is Delete collection? only when unavailable. Empty Unsorted says No unsorted batches. Under exactly `(hover: none) and (pointer: coarse)`, the first-run Canvas (an empty Unsorted feed) shows Write a prompt, pick a model, tap Generate.; otherwise it keeps the keyboard hint, with one accessible variant. An empty Pinned scope (Nothing pinned yet) and an empty collection (This collection is empty) have their own title and body and no generate hint. These exceptions are synchronized in the locked handoff owners without new tokens.
- **Type: no `text-transform: uppercase`, no middle-dot joins, mono only for kbd, template tokens and the resolved prompt.** Labels are sentence-case source text in real small caps; meta is a list; readouts (seed, counts, timers) are sans tabular numerals; buttons say the verb, no arrow glyph. No subtitles: a heading stands alone; counts and identifiers move into body, fields or Meta lists, or are dropped; field labels, body paragraphs and one-sentence notes are not subtitles.
- **Field focus has one owner: `styles/field.module.css`.** Every text input, textarea and select composes `control` (a field with its own border), its wrapper composes `frame` (a well that frames a borderless field, as `dialog.module.css` `.fieldWell` does), or it composes `bare` (a borderless inline field, underlined on focus). The edge is the field's border plus a flush 1px outline in `--focus-ring`; never give a field the 2px offset ring that buttons use, and never declare a field focus rule of your own. `global.css` loads after the modules, so a rule that removes a control's ring needs more specificity than the bare `:focus-visible` (0,1,0), such as `.x:focus-visible { outline: none }`, not a plain `.x { outline: none }`. A rest state that recolours a field's border (invalid, tuned) is scoped to `:not(:focus-visible)` so focus wins. `test/designSystemDrift.test.ts` pins the rules and the list of fields.
- **The desktop Composer yields the viewport to the feed.** A press on the feed's rows (batches and tiles, `[data-virtualized="canvas"]`; an empty Composer yields to any press outside it, while one holding a draft ignores presses on a feed state with nothing to view, the view header, the sidebar or a dialog), a reader scroll of the feed of more than 24 px (`Composer/composerYield.ts`, called from Canvas), or 6 s (`COMPOSER_IDLE_YIELD_MS`, `useComposerIdleYield`) without pointer movement, key presses or focus inside it while work is running (`useHistoryWorkRunning`, a drain or prompts in preparation) minimizes it to the collapsed bar, whether or not it holds text; the draft is untouched. It stays open while the pointer rests on it, an owned popover, menu, listbox or dialog is open, an upload is running, an IME composition is active, or an error forces it open. Idle alone never closes it on a reader who is composing: while a Composer text field has focus, the reader has typed in it since the last submit and it no longer holds what that submit sent, the idle delay does not yield (a reader scroll or a press on the feed still does, and after a submit with no further edits, or once the text is back to what was sent, it yields as before). "Outside" is decided by the pointer's coordinates against the Composer's box, so a press that WebKit hit-tests through the captured dock, or that lands on the root while a view transition is prepared, never counts as outside. It expands only on intent: activating the bar, typing a printable character on the focused bar (inserted once, at the caret the field had when it minimized and replacing its selection, so typing resumes in place; a field the reader has not focused since it mounted, as after returning from another view, has no caret of theirs and takes the character at the end), a tile handoff, a file drag or a forced error; new results never expand it. Generate and Stop rescue a click delivered to the root element while hit-testing is suspended (`useRootClickRescue`), unless the Composer is behind a modal (`behindModal`: an `inert` sweep or a native modal dialog). A reader scroll is a wheel, a touch move, a scroll key (not one a menu, listbox, dialog or text field uses itself) or a mouse drag of the scroller's scrollbar strip; the feed's own scrolls never count. Phones keep their own model (collapsed by default, a sheet when open).
- **Limited-height image Composer**: only `(width >= 768px) and (height <= 620px)` compacts the image body, sharing Attach and the prompt when there are no references and limiting the prompt to three lines plus padding. That shared-row textarea reserves the existing absolute Minimize hit region with `width: calc(100% - 28px - 16px)`, using `44px` instead of `28px` under the capability gate. With references, composer content width >=640px shares that row: top-aligned references wrap within 40cqi with 4px end padding; the prompt keeps the same Minimize reservation. Narrower reference composers keep separate rows. Phone, inventory/error-only and video bodies retain their layouts; the textarea's 44px touch minimum stays under the capability gate. Soft informational toasts omit their glyph; success/default keeps the check and error keeps the alert, with existing lifecycle and motion unchanged.
- **Approved batch header hierarchy**: at viewport width >=768px, the one-line prompt reserves `max(240px, 50% of the header)` before meta and actions wrap below with actions end-aligned. The existing intrinsic flex structure keeps ordinary wide headers on one row when the cluster fits. Phone geometry and its 96px meta minimum, direct-action order, names, anchors and capability-based touch floors stay unchanged.
- **Don't re-roll shared scaffolds.** Canonical owners:
  - Type primitives → `styles/type.module.css` (`.label` small caps, `.meta` list, `.numeral` tabular readout, `.kbd`), composed by modules. Meta strings → `components/Meta` (`<Meta items lead>`, drops empty items; on-dark hosts retint through `--meta-ink` / `--meta-ink-strong`).
  - Etched art → `components/Etching` (`<Etching id>`, `EtchingId`), the only owner of an artwork `mask` (WebP alpha masks in `assets/etch/`). Empty, error, crash and loading presentation → `components/StateView` (`art` puts the etching in the `.plate`; `restPlate` is the empty plate at rest for loading; `glyph` for icon-only fallbacks); `LoadingState` / `ErrorState` wrap it.
  - Reduced motion → the single rule set at the end of `styles/motion.css` (collapses every `--m-*`, `--dur-*` and `--ease-*`, and the `::view-transition-*` pseudos); sheet slides and looping loaders, which no token reaches, add an owner-local branch. View navigation → the keyed `<ViewTransition>` around the view stage in `App.tsx`, direction from `lib/viewNav.ts` `viewNavDirection`. Composer has a separate opacity-only enter/exit boundary for managed-view navigation; its `composer-frame` update class interpolates the frame's footprint when a part enters or leaves or the mode body (`composer-body`) swaps, and typing never animates it (the prompt is not in the Composer's parts snapshot). Both update classes are keyed to the `composer-parts` Transition type (`lib/composerMotion.ts`), which only the Composer's parts commit carries (a typed `startTransition`, because `useDeferredValue` cannot carry a type), and only when a part appears or leaves (`composerPartsReshaped`; a queue emptying and refilling during a drain pass does not count), so any other Transition leaves them unnamed: a captured element is not hit-testable until its animation ends, and a frame captured while a batch enters the feed, or while a press bumps the queue count, would swallow Generate presses. While the queue drains, Stop sits beside Generate, never in its place: a press then joins the queue. Conditional parts (Composer banner, ref chips, queue chip and list, collapsed-bar badges, busy pill; Batch queue badge, pin and Play master; picker phase bodies and warnings; Lightbox reference strip and image error; Sidebar empty/error state via `StateView`; Diagnosis card; Settings panel states; Connection result and test report sections) → an unnamed `<ViewTransition default="none" enter="part-enter" exit="part-exit">` rendered from the surface's one deferred snapshot; urgent input (typing, focus, ticked boxes) never goes through it. A part inside a hidden surface (the collapsed Composer form, the closed queue) is kept out of the capture with `view-transition-name: none !important`, because a snapshot ignores its ancestors' opacity and clip. List reflow and removal → a `<ViewTransition>` per Canvas batch row (`Canvas`), per feed tile (`Batch`) and per Archive tile (`Archive`), classes `tile-move` (update), `tile-exit`, `tile-enter` in `motion.css`; each surface renders one snapshot so the removal commits in a Transition, and the boundary sits above every DOM node it animates (React runs enter/exit only there). **Background work never starts a view transition** (`lib/feedMotion.ts`): a document view transition suspends hit-testing and React's event handling while it is prepared and captures the Composer dock in WebKit while it animates, and stream events land several times a second while the reader types. Canvas and Batch therefore render from `useMotionSnapshot`, which follows the live value at once when the change is plain (Canvas: the list only grew at its newest end by batches it has not shown, `grewOnlyAtEnd`; Batch: the same tiles in the same order with the same pin, `sameRows`) and goes through a Transition only when the list is reshaped (a batch or tile leaving or coming back, an older page above the reader, a scope swap, a pin). A new batch plays its CSS entrance and a finished tile develops in place, with no capture; the rows the feed pushes up as it follows that batch are eased by `lib/feedFollow.ts` instead (an additive Web Animations transform on the virtual row window, never the list whose rectangle is the measured scroll margin, over `--dur-view` / `--ease-view`, read from the tokens at run time, skipped under reduced motion; Canvas eases each scroll the virtualizer writes through its `scrollToFn` for a short window after the append, so the follow and its estimate corrections add up into one motion and no frame paints the rows un-eased); the queue badge and Play master, which change with background status, appear and leave without a part animation. The comparison is against the rows shown, never a lagging `useDeferredValue` copy: React holds a Transition while a view transition runs, and a reshape arriving meanwhile must start from what is on screen. Archive keeps `useDeferredValue`: every change there is the reader's own. The Batch row's progress live region is portalled to `<body>`: a text change inside the row boundary would activate the row's update on every tile completion and hold the whole row non-hit-testable. A tile whose terminal body replaces its loading plate in place carries `data-seen` (the row's `entered` flag), so the develop alone marks completion and the shell plays no second entrance; an entering batch (`data-entering`) owns the entrance and its tiles play none; every entrance uses `backwards` fill, never `both`, so no held end pose outranks the hover lift or the press. A feed removal (Archive, Dismiss, Cancel, Unpin, a move out of the scope, Undo) hands keyboard focus to a successor before the node leaves (`lib/focusSuccessor.ts`: the next tile, else the previous, else the batch header, else the next row, else the scroller; Undo refocuses the restored tile). The deferred snapshot is for rendering only: every handler that mutates state, resolves an action or computes indexes or ids reads the live value (live props, or `useAtelierStore.getState()` at click time), and a control shown from a stale snapshot is inert or validated against the live value before it acts, because React holds a Transition's commit until a running view transition finishes (about `--dur-sheet`), not one frame. Where deleting a container would take the animated boundary with it, the container gets its own exit boundary: each Archive virtual row (`default="none" exit="tile-exit"`, so a removed row's sole tile still exits), and the Canvas feed column beside the empty state (the last batch's removal exits the column while `EmptyCanvas` enters with `part-enter`). Feed boundaries stay unnamed so a batch two scopes share never pairs across a view swap; Archive tiles are named `tile-<id>` with `share` so a tile that re-chunks into another virtual row moves as one group. The captures are exactly these: view stage, Composer frame and body, batch rows, the feed column and empty state, Archive rows, tiles, and the listed parts (guard in `designSystemDrift.test.ts`); React alone starts transitions and names boundaries; two CSS-named groups exist beside them, both for the feed clip. Feed view transitions stay between the view header and the Composer: where nested view-transition groups exist (Chromium) the Canvas scroller is the parent group `atelier-feed` (`view-transition-group: contain`, unnamed while React names the view stage) and `::view-transition-group-children(atelier-feed)` clips its rows and tiles to the scroller less `--composer-top`, with the header and Composer live and uncaptured. The parent group's own image pair never cross-fades (`::view-transition-old(atelier-feed)` hidden, `::view-transition-new(atelier-feed)` live and opaque): it paints everything in the scroller that is not a captured row, so the default cross-fade dissolved the whole feed on every batch entrance (`e2e/feed-fill-flicker.spec.ts`). Engines without nested groups (WebKit 26) instead capture the view header (`atelier-feed-head`) and the Composer dock (`atelier-dock`) only in a feed transition: the CSS gate is a feed boundary inside the scroller carrying React's inline `view-transition-name`, both groups sit above the feed's (`z-index: 1`), hold still with no cross-fade, and the header group paints `--bg` behind its transparent snapshot. There a captured dock is not hit-testable and a press on it would land on the feed scroller, so the Composer registers its box with `protectPresses`: such a press ends the transition and is re-aimed (the input guard, below); typing reaches the prompt throughout. Do not style `::view-transition-old(x):not(:only-child)` in WebKit 26: it hides the new image too. A boundary that mounts starts a native view transition even with `enter="none"`, and hit-testing is suspended document-wide while the browser prepares one, so bookkeeping commits that own no motion (a roll-queue drain's take and restore) are committed urgently, outside a Transition. React handles no event in that window either: react-dom 19.3.1 switches its event system off in `commitBeforeMutationEffects` and back on in `flushMutationEffects`, and with a view transition the mutation phase waits for the browser to run the update callback, so without help a keystroke changes a field's DOM value but never reaches `onChange` (the next Composer re-render then wrote the stale draft back and threw the caret to the end), a submit shortcut does nothing, and a keyboard-activated or scripted click runs no handler; React also records the focused element before the window and refocuses it afterwards whenever focus differs, which reverted a focus move the reader made meanwhile. The window is as long as the capture takes (one or two frames at rest, up to 500 ms while React waits for fonts and images, far longer on a busy machine). **Input wins over that window** (`lib/viewTransitionGuard.ts`, mounted once by `components/ViewTransitionGuard` in `App.tsx`): it observes `document.startViewTransition` (it starts and names nothing) and, on the first key, input, composition, pointer, click or focus event of a preparation window, hands React a synchronous update before React's own listeners run. React documents the effect: a synchronous update in the middle of that sequence skips the transition and commits at once, so that one transition loses its animation and no event is lost. When the reader already moved focus, the commit's `prior.focus()` restore is a no-op for the length of that flush. A press the browser delivered to the root (preparation), or to whatever lies behind a captured `protectPresses` region (animation), is re-aimed at the element under the pointer: its default action is cancelled, a text field takes focus and the caret (`caretPositionFromPoint`), and any other control gets one click in place of the stray click that ends the press. `useRootClickRescue` remains for a click whose press began before the window. Browser tests that must act inside the window hold the update callback (`e2e/harness/composerTyping.ts`, `e2e/composer-typing.spec.ts`); tests that only need a press to land after a transition fire it on `updateCallbackDone`, never on a timer (`e2e/motion.spec.ts`, rapid archives). React waits for a running view transition and batches the Transitions committed meanwhile into the next one; a synchronous re-render while one prepares skips it, so the feed virtualizers run with `useFlushSync: false` (`lib/feedAnchor.ts`). Canvas rows sit in normal flow inside one window translated to the first rendered row (TanStack's dynamic-size layout), so a batch that shrinks or leaves moves the rows below in the same Transition commit and their boundaries animate it; per-row `translateY` would move them only after a later ResizeObserver measurement, outside the Transition. Placeholder data (`keepPreviousData` showing the previous scope or search) rides in the Canvas snapshot and keys the row list, so the commit that replaces it remounts the list instead of playing row exits and entrances; the view stage carries the swap. The sidebar, toasts and overlays stay outside every capture except their listed parts (the rail state, the Lightbox chrome, the picker phases, the report sections), which are captured only while they enter or leave. The rail keeps live rows; its seen marks live in the rail's own view of `lib/seenBatches.ts`, so a batch the rail commits one urgent pass early never counts as seen for the Canvas row that mounts a commit later (with one shared set the Canvas entrance of every new batch was lost while the sidebar was open).
  - Modal scaffold → `components/DialogShell/`. a real `<dialog>` opened with `showModal()`, so **Tab containment, background inerting, and top-layer stacking come from the platform** (`trapFocus`/`autoFocus` props are gone; `useFocusTrap` remains the tool for surfaces the top layer does NOT cover. Sidebar drawer, popovers, the Lightbox's inner chrome). Three things stay ours by design: (1) **Escape**. the native `cancel` event is `preventDefault`ed so the three-mechanism nesting discipline below stays authoritative; (2) **exit choreography** (`useExitTransition`). the `overlay` transition property is Chromium-only; (3) **focus restore**. DialogShell captures the opener in its LAYOUT effect immediately before `showModal()` (a passive effect runs after the dialog already holds focus and would capture a control inside it), and the platform's own restore doesn't survive React removing the node in the same commit. `useModalChrome({ nativeModal: true })` therefore skips both its inert sweep and its focus save/restore; popovers/drawers leave it off and still need both. Any CSS class used as a DialogShell backdrop must carry the UA `<dialog>` resets (`styles/dialog.module.css`). DialogShell is not for popovers. A dialog's row of rectangular choices (a label around a visually hidden radio, or an `aria-pressed` toggle button) composes `dialog.module.css .choiceChip`.
  - Modal view-transition isolation → `styles/motion.css` excludes every element outside native `dialog:modal` subtrees with `view-transition-name: none !important`, overriding React's inline names and the feed's CSS names in both engines. The gate is modal presence, not `inert`, so view navigation keeps its motion. Dialog parts still animate, and background captures resume on close. `DialogShell` also ends an existing transition on opening: feature-detect `document.activeViewTransition`, then skip after `ready` resolves (skipping preparation rejects `ready` with an `AbortError` that React 19.3.1 reports). Older engines finish the running view-transition pseudo animations instead. A transition snapshot paints above the platform's top layer, so `showModal()` alone cannot protect a dialog.
  - Inline create/rename → `hooks/useInlineEdit.ts` (`commitOnBlur` is the divergence prop). Vertical drag-reorder → `hooks/useVerticalDragReorder.ts` (PromptManager's `useRowReorder.ts` is the index-callback adapter).
